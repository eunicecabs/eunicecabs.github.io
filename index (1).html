04 — Process

How I work

Whether it's a database bug or a messy Drive, I follow the same four stages.

01

Understand

Read the existing code or system first, and confirm what the actual requirement is before changing anything.

02

Build

Implement the straightforward version — clean structure, no dependencies the project doesn't need.

03

Test

Check the edge cases on purpose: what happens when stock runs out, a field is empty, or the network drops mid-request.

04

Document

Write the README and setup steps so the next person — or future me — isn't guessing.
